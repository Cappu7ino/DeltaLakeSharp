# CDF And Partitioned Reads

## Summary

Change Data Feed and partitioned reads are advanced read workflows. In the public client SDK, they are V3-oriented capabilities. ADBC exposes read-only forms through its V3-backed adapter.

## Change Data Feed

Purpose:

- Read row-level changes between Delta versions.
- Query CDF rows through the `_cdf` relation.

Client APIs:

- `ReadChangeDataAsync`
- `ReadChangeDataAsDataReaderAsync`
- `ReadChangeDataAsArrowStreamAsync`
- `ExecuteChangeDataQueryAsync`
- `ExecuteChangeDataQueryAsDataReaderAsync`
- `ExecuteChangeDataQueryAsArrowStreamAsync`

Source: [../../src/DeltaLakeSharp.Client/DeltaTableServiceClient.cs](../../src/DeltaLakeSharp.Client/DeltaTableServiceClient.cs)

Constraints:

- Use V3 for public client CDF APIs.
- `startingVersion` must be non-negative.
- `endingVersion` must be greater than or equal to `startingVersion`.
- The table must have CDF enabled.
- V1/V2 Flight wrappers throw for CDF APIs.

## CDF Result Shape

CDF rows include regular table columns plus metadata such as:

- `_change_type`
- `_commit_version`
- `_commit_timestamp`

Agents should not assume only insert/delete events exist; update workflows can include preimage and postimage rows.

## Partitioned Reads

Purpose:

- Plan a table snapshot into read partitions.
- Allow independent readers to process opaque partition descriptors.

Client APIs:

- `GetReadPartitionsAsync`
- `ReadTablePartitionAsync`
- `ReadTablePartitionByTokenAsync`
- Arrow stream partition variants

Model: [../../src/DeltaLakeSharp.Client/Models/DeltaReadPartition.cs](../../src/DeltaLakeSharp.Client/Models/DeltaReadPartition.cs)

Descriptor fields:

- token
- version
- ordinal
- total partition count
- file count

## Partition Token Rules

- Tokens are opaque.
- Tokens are generated by backend planning.
- Tokens are tied to snapshot and backend semantics.
- Do not construct tokens manually.
- Do not persist tokens as long-term stable IDs.

## ADBC Behavior

ADBC exposes partitioned execution for supported read modes. It rejects combinations that would make semantics unclear, including:

- partitioned execution with CDF mode
- partitioned execution with `MaxRows`
- some deletion-vector layouts

## Agent Guidance

- Use V3 for CDF and partition APIs.
- Use streaming result handling for both workflows.
- Treat `_cdf` as the CDF SQL relation.
- Treat partition planning and partition execution as a paired workflow.
